## 알아낸 것 가운데 제출물에 쓸 것

### 우리 정책이 강좌 기준보다 느슨한 곳 (4a 노트)
- **추론 엔드포인트 바이너리.** 강좌는 `/usr/local/bin/openclaw` 하나만 허용하는데 우리는 `curl` 과
  파이썬 여럿을 열어 두었다. 강좌가 "에이전트가 선로를 벗어난" 시나리오로 분류한 구성이다.
- **`access: read-write` 는 경로를 가리지 않는다.** 강좌는 같은 호스트에 메서드와 경로 쌍 다섯 개만 연다.
- **nightshift 의 패키지 저장소 블록**이 프로토콜을 생략해 메서드도 경로도 검사하지 않는다.
- 반대로 우리가 더 엄격한 곳도 있다. `include_workdir: false` 로 작업 폴더를 읽기 전용으로 두었다.

### 우리 코드의 빈자리
- `configs/author.yml` 에 worker 모델이 선언돼 있으나 부르는 곳이 없다 (2c 노트).
- 약물감시 도구 세 개가 NAT 에 등록되지 않은 채 주석으로 남아 있다 (1c 노트).
- 도구 결과를 지시로 읽지 말라는 규칙이 작성자 프롬프트에 없다 (3c 노트).
- 도구 병렬 실행은 이미 배선돼 있다. 모델이 한 번에 부르도록 프롬프트 한 줄을 더하면 된다 (2a 노트).

### 라벨 검색 개선 판단 (2b 노트)
임베딩으로 **바꾸지 말고 덧붙인다.** 지금은 반응명이 라벨에 글자 그대로 있는지 찾아 심사위원이
확인할 수 있다. 임베딩으로 바꾸면 확인 가능한 사실이 임계치 판단으로 바뀐다. 강좌 실행 결과에서
점수가 0.1 에서 0.4 사이에 몰려 자연스러운 경계선이 없다는 것도 확인했다.
