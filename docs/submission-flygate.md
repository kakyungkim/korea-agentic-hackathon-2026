폼에 그대로 붙여 넣을 문안이다. 코드 블록 안이 제출할 내용이고 바깥은 안내다.

FlyGate

## 해결하고자 했던 문제 (Problem Definition)

```
안전성 검토자는 흩어진 근거를 모아 판단을 씁니다. 도킹 점수, 참조 친화도, 허가 라벨, 이상사례 보고입니다. 문제는 근거가 전부 맞는데 결론만 그 근거를 넘어서는 주장입니다. 서로 다른 단백질의 도킹 점수를 견주어 선택성을 말하거나, 불균형 지표를 인과로 읽는 식입니다. 숫자도 출처도 맞으니 형식 검사로 걸러지지 않고, 검토자가 읽어도 찾아내기 어렵습니다. 남으면 없는 선택성이나 없는 인과가 보고서에 실립니다. FDA와 EMA가 올해 1월 안전성 모니터링을 포함한 AI 활용 원칙을 공동으로 냈습니다. 도입을 막는 것은 모델 성능이 아니라 그 판단을 뒷받침할 방법입니다.
```

323자, 공백 미포함 247자. 기준 300자 ±10퍼센트 안.

## 서비스 소개 및 주요 기능 (Solution)

```
FlyGate는 근거를 인용한 안전성 주장이 그 근거를 넘어섰는지 가려냅니다. 후보물질 하나를 타깃 단백질부터 사람 근거까지 이어 봅니다. NVIDIA DiffDock과 AutoDock Vina 실측 두 경로로 결합을 보고, 실험 친화도를 참조한 뒤, 허가 라벨과 이상사례 보고와 문헌으로 사람에게서 어땠는지 확인합니다. 주장마다 근거 ID가 붙습니다. 크리틱이 세 단계로 검증합니다. 1단은 근거 ID 유무를, 2단은 숫자가 원본 로그와 맞는지 보고 둘 다 모델을 쓰지 않습니다. 3단만 모델이 판정합니다. 규칙 열다섯 가지는 도구 제공자와 데이터 제공자가 문서에 적은 경고에서 옮겼고, 열세 가지가 결합 근거를 두 가지가 사람 근거를 다룹니다. 평가 서른세 건에서 심어 둔 과잉해석 열여섯 건을 3단이 모두 반려했고 거짓 양성은 없었습니다. 고정 규칙만으로는 한 건만 걸러집니다. 실행은 OpenShell 정책 안에서 허용 호스트 일곱 곳만 열고 돕니다.
```

480자, 공백 미포함 368자. 기준 500자 ±10퍼센트 안.

## 활용한 핵심 기술 및 AI 모델 (Tech Stack)

```
NVIDIA Nemotron 3 Super 120B(nvidia/nemotron-3-super-120b-a12b)를 계획과 크리틱 판정에, Nemotron 3.5 Lightning 30B(nvidia/nemotron-3.5-lightning-30b-a3b)를 반복 작업에 씁니다. 두 모델 모두 build.nvidia.com NIM API(OpenAI 호환)로 호출합니다.

NVIDIA DiffDock NIM(health.api.nvidia.com/v1/biology/mit/diffdock)으로 단백질과 리간드의 결합 포즈를 예측합니다. 응답의 신뢰도 값은 포즈 타당성 지표이므로 결합 친화도로 환산하지 않습니다. NVIDIA 문서가 밝힌 한계를 크리틱 규칙에 그대로 넣었습니다.

NVIDIA NeMo Agent Toolkit 1.9.0으로 작성자 워크플로와 크리틱 워크플로를 분리했습니다. 도메인 도구 여덟 종을 NAT 함수로 등록해 에이전트가 직접 호출하고, nat eval로 크리틱 적발률을 측정합니다. 크리틱 워크플로에는 쓰기 도구가 없습니다. NeMo Guardrails 미들웨어로 가드레일 계층을 배선했습니다.

NVIDIA OpenShell 0.0.116으로 실행을 가둡니다. deny-by-default 정책으로 허용 호스트 일곱 곳만 열고, 쓰기는 지정한 출력 폴더만 허용하며, 그 밖의 접근은 차단 로그로 남습니다. 스모크 검증 열여덟 건이 모두 통과했습니다.

build.nvidia.com 스킬 카탈로그의 NVIDIA BioNeMo 에이전트 스킬 문서를 NIM 호출 규격의 참조로 썼습니다.

그 밖에 Python 3.12, 공개 데이터 소스로 openFDA FAERS, DailyMed SPL, PubMed E-utilities, RCSB PDB를 씁니다. 불균형 지표(PRR, ROR, 신뢰구간, 카이제곱)는 모델이 아니라 파이썬이 계산합니다.
```

## 계보와 기여

```
주제와 초파리 도킹 경로는 팀원 제안이고, 에이전트 하네스와 검증 체계는 선행 프로젝트 PharmaSignal v0에서 이어 온 자산입니다. 두 갈래를 하나의 파이프라인으로 이었습니다.
```

초파리 도킹 자산은 팀원의 별도 저작물이라 복제하지 않고 출처와 SHA256 을 밝혀 인용한다.
커넥톰 원본은 CC BY 4.0 이라 출처 표기가 필요하다. 자세한 기여 구분은 `docs/notes/credits.md`.
