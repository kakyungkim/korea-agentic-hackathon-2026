## 전체 조망

편이 셋이고 실험이 여섯이라 무엇이 무엇을 막고 있는지가 흩어지기 쉽다.
[STUDY.md](STUDY.md) 가 그것만 본다. 실험이 어느 그림이 되고 그 그림이 어느 절을 지탱하는지,
지금 쓸 수 있는 절이 어디인지, 무엇이 급한지가 한 장에 있다.

**실험이 끝나면 STUDY.md 를 먼저 고친다.** 편별 문서보다 앞이다.

## 이 문서들이 무엇인가

**골격이지 초고가 아니다.** 절마다 다음 셋을 적었다.

1. **무엇을 주장하는가** (한 문장)
2. **지금 있는 것** (측정과 결과 파일 경로)
3. **더 필요한 것** (실험 번호 또는 문헌)

초고를 쓸 때는 "지금 있는 것"이 채워진 절부터 쓴다. 본편은 5, 6, 7절이 이미 채워져 있다.

## 세 편을 나누는 이유

한 편에 묶으면 **도메인 심사자에게는 판정기 논의가 군더더기로, ML 심사자에게는 규제 절차가
배경으로** 읽힌다. 실제로 같은 내용인데 독자가 다르다.

겹치지 않게 선을 그었다.

| | 본편 | 별편 | 도킹 편 |
|---|---|---|---|
| 중심 질문 | 정답이 부실한 도메인에서 판정기를 어떻게 평가하나 | 누수를 어떻게 유형화하고 재나 | 도구 출력의 과잉해석을 어떻게 거르나 |
| 라벨 네 계열 | **중심** | 인용만 | 없음 |
| 누수 사다리 | 한 절 | **중심** | 없음 |
| 경로 설계 절제 | **중심** | 없음 | 없음 |
| 규칙 17종 | 방법 한 단락 | 없음 | **중심** |
| 커넥톰 대조 | 한 절 | 없음 | 없음 |

**같은 수치를 두 편의 헤드라인으로 쓰지 않는다.** 0.960 대 0.790 격차는 본편에서 누수
증거로, 별편에서 유형 분류의 사례로 쓴다. 역할이 다르면 중복 게재가 아니다.

## 공통 규율

- **모든 수치는 결과 파일에서 읽어 온다.** 원고에 손으로 적은 숫자가 있으면
  `scripts/verify_numbers.py` 가 막는다
- **OMOP 0.960 을 어느 편의 헤드라인에도 올리지 않는다.** 이름을 가린 0.790 이 주 수치다
- **표본이 작은 곳 셋**(가림 10건, Jev 대 Nemotron 34건, 파일럿 양성 12쌍)에 기댄 주장은
  실험 1과 3 전에는 쓰지 않는다
- **선행연구 인정을 서론 첫 단락에 둔다.** 음성 쌍 문제(Hauben 2016, Slattery 2016)와
  주장 강도 프레임워크(Uesawa 2026)가 우리보다 먼저다
- **카파 0.22 를 쓰지 않는다.** 도구 간 일치도이고 전문가 간 일치도가 아니다.
  Naranjo 1981 의 카파 0.21~0.40 으로 대체한다
