# 결과 파일을 그대로 화면으로

[시리즈 색인](00-시리즈-색인.md) · 앞 편은 [NVIDIA 에이전트 스택 실전](11-nvidia-스택.md)입니다.

여기까지가 만든 것이고, 이 편은 **그것을 남이 열어 볼 수 있게 만든** 쪽입니다. 심사위원이
저장소를 받아 설치하고 돌려 보는 일은 거의 없습니다. 주소 하나를 열어 봅니다.

## 무엇을 만들었나

<https://flygate.kr> 입니다. 2026-10-07 기준으로 이렇게 되어 있습니다.

| 항목 | 값 |
|---|---|
| 화면 | 21개 |
| 공용 컴포넌트 | 23개 |
| TypeScript 소스 | 58개 파일, 10,882줄 |
| 서버리스 API | `api/index.py` 319줄 |
| 커넥톰 3D 메시 | 3.9MB |

React 와 Vite 와 TypeScript 로 만들고 Vercel 에 올렸습니다. 뒤쪽은 FastAPI 를 서버리스
함수로 띄웠습니다.

화면은 크게 넷입니다. 문제와 개요를 설명하는 쪽, 사례가 지나가는 길을 보여 주는 쪽(관제,
실시간 트리아지, 타임머신), 측정 결과를 펼치는 쪽(벤치마크, 검증, 호출 기록), 그리고
커넥톰과 도킹을 시각화하는 쪽입니다. 국내 보고 서식을 다루는 화면도 따로 있습니다.

## 설계 규칙 하나가 전부입니다

**화면이 읽는 데이터는 벤치마크 스크립트가 쓴 결과 파일 그 자체입니다.**

```
pipeline/bench/*.py   →   web/public/data/*.json   →   화면
```

`bench.json` 370KB, `guard_policy_eval.json` 64KB, `literature_rerank_eval.json` 95KB 가
그대로 올라가 있습니다. 화면에 숫자를 손으로 적은 곳이 없습니다.

이 규칙 하나가 막는 것이 큽니다. **문서와 화면과 발표 자료의 숫자가 따로 노는 사고**가
여기서 구조적으로 안 납니다. 측정을 다시 돌리면 화면이 같이 바뀌고, 측정을 안 돌리면 화면도
안 바뀝니다. 수치를 고치려면 측정을 고쳐야 합니다.

반대로 비용도 있습니다. 결과 파일 형태가 바뀌면 화면이 깨집니다. 그래서 결과 JSON 의 키를
바꾸는 일을 측정 코드 쪽의 호환성 문제로 다뤘습니다.

## 정적 파일로 낸 이유

처음에는 API 가 데이터베이스를 읽어 주는 구성을 생각했습니다. 그렇게 하지 않았습니다.

- **심사 기간에 꺼지면 안 됩니다.** 서버가 죽으면 평가가 끝납니다. 정적 파일은 CDN 에서 나갑니다
- **FAERS 원자료는 55분기이고 수억 행입니다.** 그걸 올릴 수도 없고 올릴 이유도 없습니다.
  화면에 필요한 것은 집계된 결과입니다
- **재현이 쉽습니다.** 결과 파일이 저장소에 있으니 받아서 열면 같은 화면이 나옵니다

살아 있는 호출이 필요한 곳만 서버리스 함수로 뺐습니다. 실시간 트리아지와 도킹 시연입니다.

## 커넥톰 3D 를 넣을 때 걸린 것

초파리 중앙뇌 부분그래프가 뉴런 49,244개에 연결 1,051,255개입니다. **브라우저에 그대로
넣으면 열리지 않습니다.**

그래서 셋으로 나눴습니다. 뇌 영역 메시는 3.9MB GLB 하나로 미리 구워 두고, 뉴런 연결은
화면에 필요한 만큼만 뽑아 둔 부분집합을 쓰고, 나머지 수치는 집계값으로 보여 줍니다.
**원본을 다 보여 주는 것이 목적이 아니라 구조를 이해시키는 것이 목적**이라 이렇게 잘랐습니다.

여기에도 함정이 있습니다. 보여 주는 부분집합이 전체를 대표하지 않으면 보는 사람이 틀린
인상을 받습니다. 그래서 화면에 "이 화면은 부분집합입니다"를 적고 전체 수치를 함께 뒀습니다.
[10편](10-커넥톰-대조.md)에서 적은 대로 커넥톰은 비유로 쓸 때 특히 조심해야 합니다.

## 발표에서 실제로 쓴 화면

21개를 다 보여 줄 시간은 없습니다. 발표에서 쓴 것은 셋이었습니다.

| 화면 | 왜 |
|---|---|
| 관제 | 사례가 어느 경로로 갔는지 한 장에 보입니다 |
| 벤치마크 | 수치가 결과 파일에서 왔다는 것을 그 자리에서 보여 줍니다 |
| 호출 기록 | NVIDIA 를 실제로 불렀다는 증거입니다 |

**나머지 18개는 심사위원이 혼자 열어 볼 때를 위한 것**입니다. 발표용과 탐색용을 섞으면
발표가 늘어집니다.

## 이 편에서 가져갈 것

- **주소 하나를 여는 쪽이 저장소를 받는 쪽보다 훨씬 많이 봅니다.** 배포까지가 산출물입니다
- 화면이 읽는 데이터를 **측정 스크립트의 출력 파일 그 자체로** 두세요. 숫자가 따로 놀 수 없습니다
- 숫자를 손으로 적을 수 있게 만들어 두면 언젠가 손으로 적습니다
- 심사 기간에 꺼지지 않는 쪽을 고르세요. **정적 파일이 서버보다 안 죽습니다**
- 큰 그래프는 다 보여 주려 하지 말고 **부분집합이라고 적고** 전체 수치를 옆에 두세요
- 발표에 쓸 화면과 혼자 열어 볼 화면을 나누세요
