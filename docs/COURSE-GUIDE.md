# DLI 강좌 수강 안내

해커톤 온라인 사전 챌린지의 교육 미션을 혼자 헤매지 않고 끝내도록, 등록부터 진도 100%까지 필요한
것만 모았습니다. 이미 겪고 푼 오류는 원인과 해결을 그대로 적어 두었으니 같은 자리에서 시간을 쓰지
않으셔도 됩니다.

## 수강 이유와 과정 개요

과정 이름은 "Securing Agents with OpenShell and NemoClaw"(DLI S-FX-43)입니다. 무료이고 브라우저에서
돌아가며 GPU가 필요 없습니다. 4개 모듈에 약 4시간 걸립니다. 우리 프로젝트가 쓰는 에이전트 루프와
OpenShell 정책을 그대로 다루기 때문에, 강좌를 듣고 나면 저장소의 `configs/`와 `policies/`가 무엇을
하는지 바로 읽힙니다. 등록은 아래 주소에서 합니다.

https://learn.nvidia.com/courses/course-detail?course_id=course-v1:DLI+S-FX-43+V1

2. **build.nvidia.com API 키.** 무료 크레딧으로 충분합니다. 키는 각자 보관하고 서로 공유하지

   들어갑니다. `Launch NemoClaw`는 모듈 3에서 누르세요. 미리 켜 두면 실습은 못 하고 자원만 씁니다.

## 설정 단계의 Failed to fetch 대처

키를 넣고 Save & verify를 눌렀을 때 `Connection failed: Network or endpoint failure ... Failed to
fetch`가 뜨고 콘솔에 CORS 오류가 찍히는 일이 잦습니다.

**원인.** 키도 모델도 주소도 정상입니다. 강좌는 NVIDIA API를 직접 부르지 못해 릴레이 서버를 거치는데,
그 서버가 간헐적으로 504를 냅니다. 오류 페이지에는 CORS 허용 헤더가 붙지 않아 브라우저가 "헤더가
없다"고만 보고합니다. 실측으로 네 번 중 세 번이 30초 만에 실패했고, 성공한 한 번은 1.7초에 돌아왔습니다.

**해결.** 설정의 **Request handling**에서 `Automatic retries`를 0에서 **3**으로 올리세요. 대기 시간은
60초 그대로 두면 됩니다. 실패는 30초에 나고 성공은 2초 안에 오기 때문입니다.

**헛수고하지 않으셔도 되는 것.** 확장 프로그램을 끄거나 시크릿 창을 여는 일은 이 오류와 상관이
없습니다. 콘솔의 `Could not establish connection`은 확장이 내는 잡음입니다. 릴레이를 터미널에서 직접
찔러 보는 명령은 `docs/TROUBLESHOOTING.md` 4번에 있습니다.

## 실습 오류 세 가지와 대처

강좌 기본 채팅 모델 `nemotron-3.5-lightning`은 답하기 전에 생각을 먼저 쓰는 추론형입니다. 아래 셋은
모두 그 성질에서 나오므로, 설정을 다시 뒤지지 마시고 바로 대처하시면 됩니다.

**`Incomplete model decision; no move was applied.`** 미로 실습에서 나옵니다. 생각에 출력 예산을 다
쓰고 결정을 내놓지 못한 상태입니다. Debug info를 펼쳐 응답을 확인한 뒤 `model:`을 `reasoning`으로
바꿔 다시 돌리세요. 그래도 안 되면 채팅 모델을 `nvidia/nemotron-3-super-120b-a12b`로 바꿉니다(크레딧을
더 씁니다). 실패한 판도 레슨이 보여 주려는 비교의 일부라 진도에는 지장이 없습니다.

**`No displayable answer arrived.`** 채팅 실습에서 한참 기다린 뒤 뜹니다. 응답 위에
`reasoning · ~2966 tok` 같은 배지가 남습니다. 질문이 어려우면 생각만 하다 한도에 닿아 보여 줄 본문이
남지 않습니다. 실측으로 같은 질문이 2,966 토큰을 생각에 쓰면 실패했고 1,455 토큰이면 본문까지
나왔습니다. 한 메시지에 여러 가지를 시키지 말고 규칙과 질문을 나눠 보내거나, 상단 **Model and context
options**에서 추론 예산을 줄이고 출력 길이를 늘리세요.

**본문이 나오다가 사라지는 경우.** 답이 쌓이다 갑자기 오류로 바뀝니다. 재시도를 3으로 올려 두어도
소용없는데, 재시도가 스트리밍이 시작되기 전에만 걸리기 때문입니다. 질문을 짧게 나눠 다시 보내고,
끊긴 자리는 `rewind here`로 되돌리거나 New chat으로 새로 시작하세요. 시간을 조금 두고 재시도하면
대체로 통과합니다.

## 진도 계산 방식

미리 알아 두지 않으면 같은 실습을 두 번 하게 됩니다.

- 체크포인트가 11개이고 **연속으로 달성한 가장 높은 지점**으로 진도가 계산됩니다. 중간을 건너뛰면
  뒤를 채워도 오르지 않습니다.
- 모듈 1과 2를 마치면 50%입니다. 그 위로는 Brev 인스턴스(launchable)가 살아 있어야 하고, 100%는
  모듈 4b까지 마쳐야 채워집니다.
- **원격 진도 기록은 기본으로 꺼져 있습니다.** 도구 모음의 Activity 패널에서 켜야 서버에 남습니다.
  꺼진 상태에서도 화면의 퍼센트는 올라가지만 브라우저 로컬 저장소에만 남습니다.
- 각 레슨의 실습을 **실제로 돌려야** 올라갑니다. Run 버튼과 채팅 위젯을 눌러 성공한 셀만 세므로,
  읽고 넘어가면 0%입니다. 한 체크포인트가 셀 두 개를 함께 요구하는 곳도 있습니다.

| 체크포인트 | 진도 | 필요한 환경 |
|---|---|---|
| `01a:model-call-verified` | 10% | 브라우저 |
| `01b:react-loop-complete` | 15% | 브라우저 |
| `01c:tool-roundtrip-complete` | 25% | 브라우저 |
| `02a:routed-workflow-complete` | 35% | 브라우저 |
| `02b:grounded-answer-complete` | 45% | 브라우저 |
| `02c:deep-research-complete` | 50% | 브라우저 |
| `03a:nemoclaw-connected` | 60% | Brev 인스턴스 |
| `03b:workspace-inspected` | 70% | Brev 인스턴스 |
| `03c:scheduled-run-complete` | 80% | Brev 인스턴스 |
| `04a:policy-boundary-verified` | 90% | Brev 인스턴스 |
| `04b:live-agent-operated` | 100% | Brev 인스턴스 |

수료 처리는 진도가 100%가 되어야 4c 페이지의 Finish Course 버튼으로 열립니다. 다만 수료증이 발급되는지,
해커톤 제출에 어떤 형태의 증빙이 인정되는지는 강좌 페이지에서 확인되지 않았습니다. [unverified]

## 모듈별 내용 요약

### 모듈 1. 에이전트 루프와 도구

에이전트를 인지, 추론, 행동이 이어지는 하나의 루프로 정의하고 그 가운데 추론 단계만 언어모델로
갈아끼웁니다. 모델 호출은 상태를 갖지 않으므로 기억은 내 코드가 들고 매번 다시 보내는 `messages[]`
배열이고, 루프를 멈추는 신호는 응답의 `finish_reason` 한 필드입니다. `stop`이면 답을 쓴 것이고
`tool_calls`면 내 코드가 함수를 실행해 결과를 붙인 뒤 다시 부르라는 뜻입니다. 여기에 도구를 붙이면
ReAct가 되고, 도구 하나 뒤에 서브에이전트를 숨기거나 MCP 서버에서 도구 목록을 받아 와도 "모델이
요청하고 내 코드가 검증한 뒤 실행한다"는 계약은 그대로 갑니다. 실습은 `if` 문으로 도는 반사 에이전트,
미로의 결정 함수를 DFS, BFS, A*로 갈아끼우는 셀, 도구 하나짜리 ReAct 루프를 바닥부터 만드는 셀로
이어집니다. 강좌가 못 박는 구분은 하나입니다. 스키마는 설명일 뿐 검증이 아니므로, 돌아온 도구 이름과
인자를 직접 확인한 뒤에 실행해야 합니다.

**우리 프로젝트와의 접점.** `configs/author.yml`의 `tool_calling_agent`와 `max_iterations: 8`이 이
루프와 걸음 수 상한에 그대로 대응하고, `src/harness/register.py`의 도구 선언이 강좌의 도구 스키마
자리입니다.

### 모듈 2. 워크플로, 검색, 딥 리서치

루프 바깥에 구조를 얹습니다. 도구를 부르기 전에 계획을 먼저 쓰는 ReWOO, 고정된 enum으로 전문가를
고르는 라우팅, 하나의 입력을 여러 전문가에게 동시에 흘리는 팬아웃을 차례로 만듭니다. 라우팅에서는
분류 결과가 허용 목록 밖이면 추측하지 말고 거부하라고 강조합니다. 이어서 검색을 도구로 감싼 Index
Agent를 만들고, 질의와 구절을 구분하는 `input_type`, 작은 청크로 찾고 부모 문서를 돌려주는 기법,
임베딩 모델을 바꾸면 색인이 통째로 무의미해지는 실패를 다룹니다. "천 개 문서를 관통하는 주제가
무엇인가" 같은 전역 질문에는 top-K가 닿지 못하므로 GraphRAG가 커뮤니티별 요약을 거쳐 답을 만듭니다.
마지막 레슨은 플래너가 실행 시점에 분기를 나누고, 워커가 공유 파일에 근거를 남기고, 종합 단계가 그
파일만 읽어 답을 쓰는 딥 리서치 워크플로입니다.

**우리 프로젝트와의 접점.** 작성자와 크리틱을 두 워크플로로 나눠 둔 구조가 강좌의 전문가 분리와 같고,
`src/harness/critic.py`의 규칙 검사가 "라우터는 고정 코드로, 판단만 모델로"에 해당합니다.

### 모듈 3. NemoClaw 스택과 상시 가동

브라우저 안에서만 살던 루프를 Brev 인스턴스 위의 상주 런타임으로 옮깁니다. OpenClaw 게이트웨이의
WebSocket이 JSON-RPC로 세션과 도구를 실어 나르고, 클라이언트는 대화 기록 대신 `sessionKey` 한 줄만
보냅니다. 에이전트의 성격과 규칙은 워크스페이스 파일(`SOUL.md`, `AGENTS.md`, `MEMORY.md` 등)이
정하는데, 에이전트가 그 파일을 스스로 고칠 수 있다는 점에서 지속성이 곧 위험이 됩니다. 마지막
레슨은 사람 없이 시작되는 실행을 다룹니다. 스킬, 하트비트, cron, 서브에이전트를 세션, 지시문
위치, 트리거 세 가지로 갈라 보고, cron 한 건을 직접 걸어 아무도 메시지를 보내지 않은 시점에 파일이
쓰이는 것을 확인합니다. 게이트웨이 토큰이 `operator.admin` 범위라 그 토큰을 읽은 사람은 곧 운영자가
된다는 경고도 여기서 나옵니다. 이 모듈부터는 Brev 인스턴스가 필요합니다.

**우리 프로젝트와의 접점.** 저장소는 OpenClaw 대신 자체 Python 하네스를 돌리므로 대응하는 코드가
없습니다. 예약 실행과 자기 컨텍스트 수정이 만드는 위험은 Night Shift 후보를 설계할 때 참고하면 됩니다.

### 모듈 4. OpenShell 정책과 CLI 에이전트 비교

권한을 커널에서 잘라 내는 OpenShell을 다룹니다. 네트워크 네임스페이스와 정책 프록시, Landlock,
seccomp, 비루트 신원 네 가지가 각각 "어디로 접속할 수 있는가", "어떤 파일에 닿는가", "어떤 커널
연산을 요청할 수 있는가", "얼마나 큰 권한으로 시작하는가"에 답합니다. 정책 YAML은 egress를 기본
거부로 두고 이름 붙인 블록 하나가 목적지 한 묶음을 여는 구조이며, 같은 호스트라도 **어느 바이너리가
접속하는지**까지 봅니다. 실습에서는 살아 있는 정책을 읽고, 특정 요청이 허용될지 먼저 예측한 뒤 실제로
실행해 두 결과를 맞춰 봅니다. 그다음 레슨은 Claude Code, Codex CLI, Cursor, Hermes, OpenClaw의 기본값을
비교하고 자유도 여섯 가지를 공격면으로 정리합니다. 두 모듈이 함께 남기는 결론은 하나입니다. 샌드박스는
권한의 크기를 줄일 뿐, 허용된 채널 위를 흐르는 바이트의 의미는 판단하지 못합니다.

**우리 프로젝트와의 접점.** 여기가 우리 `policies/`와 바로 이어집니다. `base.yaml`,
`pharmasignal.yaml`, `nightshift.yaml`이 쓰는 키가 모두 이 레슨에 나오고, 강좌 기준선과 우리 파일을
줄 단위로 대조한 결과는 `docs/notes/dli-course/module3-4.md`의 "우리 정책 파일과의 대조" 절에 있습니다.
이 모듈을 듣고 나면 그 대조표의 지적을 그대로 정책 수정에 옮길 수 있습니다.
