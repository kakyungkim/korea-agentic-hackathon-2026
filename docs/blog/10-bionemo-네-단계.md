# 구조에서 결합까지: BioNeMo NIM 네 종

[시리즈 색인](00-시리즈-색인.md) · 앞 편은 [근거 등급을 만들다 두 번 틀린 이야기](09-근거-등급.md)입니다.

앞의 아홉 편이 시판 후 이야기였습니다. 이 편은 시판 전, 곧 약을 만드는 쪽입니다.
표적 단백질과 후보 물질을 받아 네 단계를 지납니다.

```
MSA-Search      닮은 서열을 모아 줄을 맞춘다
   ↓
OpenFold3       그 정렬에서 단백질 구조를 예측한다
   ↓
DiffDock        약물이 어디에 어떤 자세로 붙는지 계산한다
   ↓
Boltz-2         붙는 세기를 예측한다
```

전부 `health.api.nvidia.com`의 NIM을 HTTP로 부릅니다. 무거운 프레임워크가 필요 없고
`httpx` 하나로 됩니다.

## 첫 관문은 권한입니다

`GET https://health.api.nvidia.com/v1/models`를 부르면 **404**가 옵니다. 모델 목록 엔드포인트가
없습니다. 생물학 NIM은 이름 기반 경로에 있습니다.

```
health.api.nvidia.com/v1/biology/mit/diffdock
health.api.nvidia.com/v1/biology/mit/boltz2/predict
health.api.nvidia.com/v1/biology/colabfold/msa-search/predict
health.api.nvidia.com/v1/biology/openfold/openfold2/predict-structure-from-msa-and-template
```

GET으로 부르면 **405**가 오는데, 경로는 맞고 메서드만 틀렸다는 뜻이라 이 자체가 좋은 확인
신호입니다.

다만 코드를 쓰기 전에 POST를 최소 한 번 보내 보세요. 계정에 Public API Endpoints 권한이
없으면 생물학 NIM이 전부 에러로 돌아오고, 권한 요청은 답이 오는 데 며칠 걸립니다. 여기서
막히면 뒤가 전부 무너집니다.

이때 응답 헤더의 `Nvcf-Status`를 함께 보세요. `fulfilled`가 아니면 200이어도 실패라,
**200을 성공으로 읽으면 안 되는 경우**입니다. 저희는 니라파립 SMILES로 DiffDock을 불러
HTTP 200에 4.1초, `Nvcf-Status: fulfilled`를 받고서야 코드를 쓰기 시작했습니다.

## 인자 이름이 문서마다 다릅니다

실제로 걸린 것만 적습니다.

| 도구 | 함정 |
|---|---|
| DiffDock | 블루프린트 노트북은 `num_steps`, 공식 예제는 **`steps`** |
| DiffDock | SMILES를 넣을 때 `ligand_file_type`은 `"smiles"`가 아니라 **`"txt"`** |
| Boltz-2 | MSA 키는 `data`가 아니라 **`alignment`** |
| OpenFold2 | OpenFold3의 `inputs`나 `molecules` 필드를 쓰면 안 된다 |
| MSA-Search | `databases`가 **대소문자를 구분한다** |

**422가 오면 다른 쪽으로 바꿔 보세요.** 저희는 alias를 두고 422면 폴백하게 만들었습니다.

Boltz-2의 MSA 키 문제는 NVIDIA 원문이 직접 적어 두었습니다. "Older examples that use `data`
fail with HTTP 422 on the validated Boltz2 NIM"입니다. 실제로 그 때문에 요청이 100퍼센트
실패한 사례가 보고돼 있습니다. 모르는 필드를 보내면 조용히 무시하지 않고 422로 막습니다.

OpenFold2는 MSA가 없으면 422입니다. 맞은 서열이 0건이어도 **MSA 필드 자체는 있어야** 합니다.
그리고 MSA-Search 응답의 키 이름이 요청할 때 준 이름과 다릅니다. 받은 대로 다음 단계에
넘기면 안 됩니다.

## 만든 쪽이 금지한 추론

여기서도 같은 규율이 붙습니다. DiffDock 응답의 신뢰도 값은 **포즈가 그럴듯한 정도이지 결합
세기가 아닙니다.**

NVIDIA 문서가 직접 적어 두었습니다.

> Do not convert confidence directly into binding affinity.

원논문(DiffDock, arXiv:2210.01776)에서도 그 값은 포즈가 기하학적으로 맞을 확률이고 에너지
축이 아닙니다. 그래서 이 문장이 그대로 크리틱 규칙으로 들어가 있는데, 만든 쪽이 스스로
금지한 추론을 검사하는 것이라 취향 다툼이 되지 않습니다.

같은 방식으로 들어간 규칙들입니다.

- **교차 타깃 순위 금지.** 서로 다른 단백질의 도킹 점수를 견줘 선택성을 말할 수 없습니다
- **친화도 환산 금지.** 도킹 점수를 결합상수로 옮길 수 없습니다
- **도구 간 점수 혼용 금지.** DiffDock 점수와 다른 도킹 도구 점수를 같은 축에 놓을 수 없습니다
- **예측 구조를 실험 근거로 쓰지 않기.** 예측된 구조는 가설이고 결정된 구조가 아닙니다
- **구조 예측 신뢰도 지표 해석 제한.** pLDDT 같은 값이 무엇을 뜻하는지 넘어서 읽지 않습니다

## 우리가 직접 잰 규칙 하나

호스팅 DiffDock API에 시드 파라미터가 없습니다. 그래서 같은 수용체와 같은 리간드를 두 번
부르면 결과가 갈립니다.

```
1차:  [0.798, 0.751, 0.725]
2차:  [0.761, 0.693, 0.515]
```

세 번째 포즈가 0.725에서 0.515로 떨어졌습니다. **단일 호출 결과로 재현성을 주장할 수
없다는 규칙의 1차 근거가 남의 논문이 아니라 우리 측정입니다.**

확률적 생성 모델을 API로 쓸 때는 일반적으로 확인할 값어치가 있습니다. 같은 입력을 두 번
보내 보고, 시드가 없으면 갈립니다.

- 같은 입력을 두 번 보내 보세요. 재현성 주장을 할 수 있는지 그것으로 압니다
